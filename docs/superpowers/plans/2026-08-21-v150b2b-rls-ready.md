# RailOps v150B-2B RLS-Ready Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rendre RailOps compatible avec des RLS strictes sans modifier le comportement métier validé de la v149, en conservant l’Admin propriétaire et les cinq contextes d’accès.

**Architecture:** La v149 reste intacte sur `main`. La branche `security/v150b2b-rls-ready` ajoute une couche Supabase Auth/RPC sûre puis adapte le client avant toute fermeture des anciennes policies. Les écritures terrain sensibles passent par des RPC contrôlées ; les imports Chef restent compatibles avec le registre actuel. La fermeture RLS sera une migration distincte, appliquée uniquement après validation locale et en ligne.

**Tech Stack:** HTML/JavaScript mono-fichier, Supabase JS v2, PostgreSQL/RLS, Supabase Auth, Edge Functions, GitHub/Vercel.

**Spec:** architecture métier RailOps validée dans le projet et état v149/v150A/v150B-1/v150B-2A.

## Global Constraints

- `main` reste la version stable tant que v150B-2B n’est pas validée.
- Ne jamais modifier la purge hebdomadaire des états/historiques de vérification.
- Ne pas modifier le moteur Import/Multi-chantier sauf adaptation d’accès serveur strictement nécessaire.
- `is_admin=true` reste le privilège propriétaire global, distinct du rôle métier `chef`.
- Le propriétaire ouvre RailOps en **mode Chef par défaut** avec son périmètre métier ; le périmètre global n’est utilisé qu’en **mode Administration explicite**.
- Chef : propres chantiers et descendants uniquement.
- Agent/CTE : chantiers affectés uniquement.
- Chef de chantier : statistiques globales actives, aucune référence/QR/scan matériel.
- Aucun navigateur ne doit recevoir `users.mdp`.
- `deleted_ids` doit continuer à empêcher la résurrection des lignes supprimées/parasites.
- Aucune ancienne policy ouverte n’est supprimée avant validation de l’application compatible.
